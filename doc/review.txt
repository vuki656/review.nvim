1. INTRODUCTION                                          *review-introduction*
                                                                 *review.nvim*

review.nvim is a diff reviewer for Neovim built around handing feedback back
to a coding agent. It opens a dedicated tab with a sidebar of git panels and a
diff pane, lets you attach typed comments (note, fix, question) to individual
lines, and exports every comment as markdown with surrounding diff context to
the clipboard, a file, or a tmux pane.

It also covers the git operations you need part way through a review: stage,
unstage, commit, amend, push, pull, checkout, create and delete branches, and
soft-reset the last commit.

Nothing about it requires an agent. It works as a plain diff reviewer too.

==============================================================================
2. REQUIREMENTS                                          *review-requirements*

Required:

  - Neovim 0.10 or later. The version is checked when the plugin file loads;
    on older versions review.nvim reports an error and does nothing.
  - git, on your $PATH.

Optional:

  - tmux. Needed only by |:Review| send and by the "Copy & Send to tmux" exit
    option. Every other feature works without tmux installed.
  - nvim-web-devicons, for file type icons in the Files and Comments panels.
    Without it the icon column renders empty.
  - Tree-sitter parsers for the languages you review, for syntax colouring
    inside the diff. Without a parser the diff still renders, uncoloured.

3. INSTALLATION                                          *review-installation*

The |:Review| command is registered by `plugin/review.lua`, so it exists as
soon as the plugin loads, and the defaults in |review-configuration| apply
without any further work. `setup()` is still worth calling: it registers the
plugin's highlight groups, loads existing quick comments and defines their
gutter signs, enables autosave for the review session and for quick
comments, and creates the optional global mappings. Without it the quick
comment signs are never defined, so `quick_comments.signs.enabled` has no
effect.

lazy.nvim: >lua

    {
        "vuki656/review.nvim",
        opts = {},
    }
<
With options: >lua

    {
        "vuki656/review.nvim",
        config = function()
            require("review").setup({
                keymaps = { toggle = "<leader>rv" },
            })
        end,
    }
<
To lazy-load, give lazy.nvim its own trigger. Until that trigger fires the
plugin is not loaded, so `keymaps.toggle` does not exist either. Use lazy's
`keys`: >lua

    {
        "vuki656/review.nvim",
        cmd = "Review",
        keys = {
            { "<leader>rv", "<cmd>Review<cr>", desc = "Toggle review" },
        },
        opts = {},
    }
<
packer.nvim: >lua

    use({
        "vuki656/review.nvim",
        config = function()
            require("review").setup({})
        end,
    })
<
vim-plug: >vim

    Plug 'vuki656/review.nvim'
    " after plug#end():
    lua require("review").setup({})
<

4. LAYOUT                                                      *review-layout*

|:Review| opens a new tab made of floating windows: a sidebar on the left and
the diff on the right. >

    ┌─ Branch ────────┐┌───────────────────────────────┐
    ├─ Files ─────────┤│                               │
    │                 ││                               │
    ├─ Branches ──────┤│            diff               │
    │                 ││                               │
    ├─ Commits ───────┤│                               │
    │                 ││                               │
    ├─ Comments ──────┤│                               │
    └─────────────────┘└───────────────────────────────┘
<
Branch is a read-only line naming the current branch. Files, Branches,
Commits and Comments are focusable panels. The sidebar takes a percentage of
the screen width set by `ui.file_tree_width`.

<Tab> cycles Files -> Branches -> Commits -> Comments -> Files. `h` and `l`
walk the same chain without wrapping. <C-l> jumps from any sidebar panel to
the diff pane; <C-h> jumps from the diff pane back to Files. <C-n> hides and
restores the entire sidebar.

Set `ui.number_navigation` to enable numeric section navigation: `1` focuses
Files, `2` Branches, `3` Commits, `4` Comments and `0` the diff pane. It is
disabled by default. In side-by-side mode, `0` focuses the new (right) pane.

The diff pane renders unified by default and can be flipped to side-by-side
with `S`, or by setting `ui.diff_view_mode` to "split".

==============================================================================
5. COMMANDS                                                  *review-commands*

                                                                     *:Review*
:Review                 Toggle the review UI.

:Review close           Close the review UI.

:Review export          Copy every comment to the clipboard as markdown.

:Review send [{target}] Send comments to `export.on_export` when it is set,
                        otherwise paste them into a tmux pane. {target}
                        defaults to `tmux.target` and applies to the tmux
                        path only. The tmux path fails if Neovim is not
                        running inside tmux.

:Review commit {sha}    Set the diff base to {sha}. Reopens the UI if it is
                        already open.

:Review pick [{count}]  Open a picker of the last {count} commits (default
                        20) and reopen the review against the chosen one.
                        Choosing "HEAD" returns to reviewing the worktree.

:Review qc              Add a quick comment on the current line of the
                        current buffer. Works outside the review UI.
                        Accepts a range, so `:'<,'>Review qc` attaches the
                        comment to the selected lines and exports it as
                        `**Lines 42-50**`.

:Review qp              Toggle the quick comments panel.

:Review log             Open the plugin log file in a new tab.

6. LUA API                                                        *review-api*

>lua
    local review = require("review")

    review.setup(opts)     -- optional; see |review-configuration|
    review.toggle()
    review.open()
    review.close()
    review.export()        -- markdown to clipboard
    review.send(target)    -- markdown to export.on_export, else tmux
    review.is_open()       -- boolean
    review.get_state()     -- current state table
    review.reset()         -- reset state
<
Quick comments have their own module: >lua

    local qc = require("review.quick_comments")

    qc.add()               -- comment on the current line
    qc.add(42, 50)         -- comment on lines 42 to 50
    qc.add_visual()        -- comment on the current visual selection
    qc.toggle_panel()
    qc.open_panel()
    qc.close_panel()
    qc.export()            -- copy to clipboard
    qc.copy()              -- copy to clipboard, then clear all comments
<

7. MAPPINGS                                                  *review-mappings*

Every mapping below is buffer-local to the review UI; none of them touch your
normal buffers. Press `?` in the Files, Branches, Commits or Comments panel,
or in the diff pane, for a help overlay listing that panel's mappings.

When `ui.number_navigation` is enabled, `1`-`4` focus the corresponding
sidebar panel and `0` focuses the diff pane. These mappings are not installed
when the option is disabled, preserving normal-mode counts and the usual `0`
movement inside the review UI.

------------------------------------------------------------------------------
7.1 Files panel                                        *review-mappings-files*

    j / k         Next / previous entry. Skips section headers and loads the
                  entry's diff.
    <CR>          On a file: load the diff and move focus to the diff pane.
                  On a directory: collapse or expand it.
    <Space>       Stage or unstage. On a directory, or on the "/" root node,
                  applies to every file underneath.
    e             Open the real file at its first change, closing the review.
    L             Show the file's full path in a popup.
    R             Refresh the file list.
    `             Toggle tree view and flat list view.
    S             Toggle unified and side-by-side diff.
    { / }         Shrink / expand the number of diff context lines.
    c             Commit staged changes. Opens a Subject and Description
                  popup; <Tab> switches fields, <CR> in Subject confirms,
                  `q` or <Esc> cancels.
    A             Amend staged changes into the last commit. With nothing
                  staged, offers to stage everything first.
    d             Revert the file's changes. Confirms first.
    P             Push to remote.
    B             Focus the Commits panel.
    <C-n>         Hide or restore the whole sidebar.
    J / K         Scroll the diff pane down / up.
    <Tab> / l     Focus the Branches panel.
    <C-l>         Focus the diff pane.
    <Esc>         Reset the diff base back to HEAD. Does nothing unless a
                  branch or commit is currently selected.
    q             Close the review.
    ?             Show the help overlay.

Staging and committing are disabled while a commit or branch is selected as
the base; the plugin reports this rather than acting.

------------------------------------------------------------------------------
7.2 Diff pane                                           *review-mappings-diff*

    c             Add a comment on the current line. In visual mode, the
                  comment covers the selected lines and exports as a range
                  such as `file.ts:42-50`.
    dc            Delete the comment on the current line, or on any line
                  covered by a multi-line comment.
    ]c / [c       Next / previous hunk, wrapping at the ends.
    ]f / [f       Next / previous changed file, wrapping at the ends.
    e             Open the real file at the current line, closing the
                  review. Unlike the Files panel, this raises the exit menu
                  when comments exist.
    S             Toggle unified and side-by-side diff.
    { / }         Shrink / expand the number of diff context lines.
    <C-n>         Hide or restore the sidebar.
    <C-h>         Focus the Files panel. In side-by-side mode, from the right
                  pane this focuses the left pane instead.
    <C-l>         In side-by-side mode, from the left pane focus the right
                  pane.
    <Esc>         Focus the Files panel, resetting the base to HEAD if a
                  branch or commit was selected.
    q             Close the review.
    ?             Show the help overlay.

In side-by-side mode `c` and `dc` are bound only on the right (new) pane.
Diffs of lock files (package-lock.json, yarn.lock, Cargo.lock and similar)
are deliberately not rendered. A binary file renders as "Binary file — no
diff to display." rather than an empty pane.

------------------------------------------------------------------------------
7.3 Comment input                                      *review-mappings-input*

The floating input opened by `c`, by |:Review| qc, and by the quick comment
mapping.

    <CR>          Submit. Bound in both insert and normal mode.
    <Esc>         Cancel. Bound in both insert and normal mode.
    <C-c>         Cancel. Insert mode.
    <S-CR>        Insert a newline instead of submitting.
    <Tab>         Cycle the comment type forwards: Fix -> Note -> Question.
                  Diff pane comments only.
    <S-Tab>       Cycle the comment type backwards. Diff pane comments only.
    <C-t>         Open the template picker. Diff pane comments only.

Submitting an empty input also discards the comment. Quick comments have no
type and no templates, so their input binds only <CR>, <Esc>, <C-c> and
<S-CR>. In the template picker, press a template's key to apply it, or
<Esc>, `q` or <C-t> to back out. A template whose text ends in ": " leaves
the cursor at the end for you to finish the sentence; any other template
submits immediately.

------------------------------------------------------------------------------
7.4 Branches panel                                  *review-mappings-branches*

    j / k         Next / previous branch.
    <CR>          Diff the main branch against the selected branch.
    <Space>       Check out the branch. Refuses on a dirty worktree.
    p             Pull from remote.
    n             Create a new branch from the selected one.
    d             Delete the branch. Confirms first, and refuses to delete
                  the branch you are on.
    P             Push to remote.
    <C-d> / <C-u> Scroll the diff pane down / up.
    <Tab> / l     Focus the Commits panel.
    h             Focus the Files panel.
    <C-l>         Focus the diff pane.
    <Esc>         Reset the diff base back to HEAD.
    q             Close the review.
    ?             Show the help overlay.

------------------------------------------------------------------------------
7.5 Commits panel                                    *review-mappings-commits*

    j / k         Next / previous commit. Moving previews that commit's full
                  diff in the diff pane without changing the file list.
    <CR>          Set the diff base to that commit and browse its files.
    u             Uncommit: soft-reset the most recent commit. Confirms
                  first, and only works on the newest commit.
    P             Push to remote.
    <C-d> / <C-u> Scroll the diff pane down / up.
    <Tab> / l     Focus the Comments panel.
    h             Focus the Branches panel.
    <C-l>         Focus the diff pane.
    <Esc>         Reset the diff base back to HEAD.
    q             Close the review.
    ?             Show the help overlay.

Preview is skipped for commits touching more than 50 files, and individual
file diffs longer than 1000 lines are elided in the preview.

------------------------------------------------------------------------------
7.6 Comments panel                                  *review-mappings-comments*

    j / k         Next / previous entry.
    <CR>          Jump to the comment in the diff pane. On a directory in
                  tree view, collapse or expand it.
    d             Delete the comment. Confirms first.
    t             Toggle flat and tree grouping.
    P             Push to remote.
    <C-d> / <C-u> Scroll the diff pane down / up.
    <Tab>         Focus the Files panel.
    h             Focus the Commits panel.
    <C-l>         Focus the diff pane.
    <Esc>         Reset the diff base back to HEAD.
    q             Close the review.
    ?             Show the help overlay.

------------------------------------------------------------------------------
7.7 Quick comments panel                               *review-mappings-quick*

Quick comments are separate from review comments. They attach to any line of
any buffer outside the review UI, show as gutter signs once `setup()` has
defined them, and persist in `.git/review-comments.json`. Add one with
|:Review| qc, toggle the panel with |:Review| qp. A quick comment can cover a
range: select lines and run `:'<,'>Review qc`, or press the
`quick_comments.keymaps.add` key in visual mode. Ranged comments place a sign
on every covered line and the panel lists them as `L42-50`.

    <CR>          Jump to the comment's file and line in the previous window,
                  leaving the panel open.
    L             Preview the full comment text in a popup.
    e             Edit the comment text.
    d             Delete the comment.
    c             Copy all quick comments to the clipboard as markdown. The
                  comments are kept.
    q / <Esc>     Close the panel.

`require("review.quick_comments").copy()` copies and then clears every quick
comment, which the panel's `c` mapping deliberately does not do.

8. CONFIGURATION                                        *review-configuration*

Pass a table to `setup()`. It is deep-merged over the defaults, so you only
need the keys you want to change. The complete defaults: >lua

    require("review").setup({
        keymaps = {
            toggle = nil,
        },
        diff = {
            base = "HEAD",
        },
        ui = {
            file_tree_width = 33,
            diff_view_mode = "unified",
            number_navigation = false,
            panels = { "file_tree", "comment_list" },
        },
        tmux = {
            target = "!",
            auto_enter = false,
        },
        quick_comments = {
            keymaps = {
                add = nil,
                toggle_panel = nil,
            },
            panel = {
                width = 65,
                position = "right",
            },
            signs = {
                enabled = true,
            },
        },
        export = {
            context_lines = 3,
            on_export = nil,
        },
        auto_refresh = {
            enabled = true,
            debounce_ms = 500,
        },
        persistence = {
            enabled = true,
        },
        log_level = "WARN",
        log_file = nil,
        templates = {
            { key = "e", label = "Extract",
              text = "Extract this into a separate function/component" },
            { key = "r", label = "Rename", text = "Rename to: " },
            { key = "m", label = "Move",
              text = "Move this to a separate file" },
            { key = "t", label = "Types", text = "Add proper types" },
            { key = "h", label = "Error handling",
              text = "Add error handling" },
            { key = "p", label = "Performance",
              text = "Performance concern: " },
            { key = "s", label = "Simplify", text = "Simplify this" },
            { key = "d", label = "Delete", text = "Remove this" },
        },
    })
<
The `nil` values are unset by default: no global mappings are created unless
you supply a key, and `log_file` falls back to a path under the system temp
directory.

keymaps.toggle ~
    Global normal-mode key that toggles the review UI. Unset by default.

diff.base ~
    Git revision the diff compares against. "HEAD" means everything in the
    working tree, staged and unstaged.

ui.file_tree_width ~
    Sidebar width as a percentage of total columns, not a column count.

ui.diff_view_mode ~
    "unified" or "split" (side-by-side) when the UI opens. `S` toggles it at
    runtime.

ui.number_navigation ~
    Enable numeric section navigation inside the review UI. When enabled,
    `1` focuses Files, `2` Branches, `3` Commits, `4` Comments and `0` the diff
    pane. Disabled by default so normal-mode counts and `0` retain their usual
    behavior unless explicitly enabled.

ui.panels ~
    Sidebar panels to display. Accepts a list of panel names/aliases (e.g.,
    `{ "file_tree", "comment_list" }` or `{ "files", "comments" }`) or a table of
    boolean flags (e.g., `{ branch = false, branches = false, commits = false }`).
    Defaults to `{ "file_tree", "comment_list" }` (showing Files changed and Comments).

tmux.target ~
    Where the export is pasted. The default "!" is tmux's last active pane,
    normally the pane you switched away from to reach Neovim, which is
    usually the one running your agent. Any other target accepted by
    `tmux paste-buffer -t` works, for example a named window "CLAUDE",
    "CLAUDE.0" or a fully qualified "session:window.pane". |:Review| send
    takes a target for a single call.

tmux.auto_enter ~
    Send Enter after pasting. Off by default so you can read the prompt
    before submitting it to the agent.

quick_comments.keymaps.add ~
quick_comments.keymaps.toggle_panel ~
    Global keys equivalent to |:Review| qc and |:Review| qp. Unset by
    default.

quick_comments.panel.width ~
    Width of the quick comments split, in columns.

quick_comments.panel.position ~
    "left" or "right".

quick_comments.signs.enabled ~
    Show gutter signs for quick comments.

export.context_lines ~
    Number of lines of diff context included above and below each comment in
    the exported markdown.

export.on_export ~
    Your own delivery callback, `function(content, comments)`. {content} is
    the exported markdown, {comments} the comment tables it was built from.
    Return `false`, or raise an error, to report that the hand-off failed.

    When it is set, |:Review| send and the "Copy & Send" exit option call it
    instead of pasting into tmux. The clipboard paths, |:Review| export and
    "Exit & Copy", still copy and then call it as well. A failed hand-off on
    close keeps the saved session rather than deleting it. >lua

        require("review").setup({
            export = {
                on_export = function(content, comments)
                    local path = vim.fn.stdpath("state") .. "/review.md"
                    local lines = vim.split(content, "\n")
                    if vim.fn.writefile(lines, path) ~= 0 then
                        return false
                    end
                    vim.system({ "my-agent", "--file", path })
                    return true
                end,
            },
        })
<

auto_refresh.enabled ~
auto_refresh.debounce_ms ~
    A filesystem watcher re-renders the UI when files change on disk,
    debounced by `debounce_ms`. libuv cannot watch a tree recursively on
    Linux, so the watcher walks the git root and watches each directory
    separately, skipping `.git`, `node_modules`, `target`, `dist`, `build`,
    `.venv` and `vendor`. It stops after 2000 directories; if the repository
    is larger the remainder is not watched and a warning is written to the
    log. The list is built when the UI opens, so directories created later
    are picked up the next time it opens. Useful when an agent is writing
    while you read.

persistence.enabled ~
    Remember comments and review state between sessions. Files are written
    to `.git/review-session.json` and `.git/review-comments.json`, inside
    the git directory, so they need no .gitignore entry.

log_level ~
    "DEBUG", "INFO", "WARN" or "ERROR". See |review-troubleshooting|.

log_file ~
    Path to write the log to. Unset by default, in which case the log lands
    in `review.nvim/review.log` under the system temp directory reported by
    `vim.uv.os_tmpdir()`, typically `/tmp/review.nvim/review.log`. Temp is
    deliberate: the log is cleaned up with the rest of the directory. Set
    this to keep the log somewhere permanent. Either way the file rotates
    once it grows past 1 MB: the current file becomes `<path>.old`, any
    previous `.old` is discarded, and logging continues in a fresh file.

templates ~
    Canned comment texts reachable with <C-t> in the diff comment input.
    Each entry needs `key` (a single character), `label` (shown in the
    picker) and `text` (inserted into the input).

9. EXPORT WORKFLOW                                             *review-export*

The intended loop:

  1. Run |:Review|. The diff opens against HEAD, so you see whatever was
     just written to the worktree.
  2. Read the diff. Press `c` on a line to attach a comment, <Tab> to choose
     its type, <CR> to submit. Comments render as boxed virtual lines under
     the code and collect in the Comments panel.
  3. Press <Space> in the Files panel to stage the parts you are keeping.
  4. Press `q`. If there are comments, an exit menu appears:

       Exit, Copy & Send to tmux   Copy to the clipboard and paste into the
                                   configured tmux target, or hand off to
                                   `export.on_export` when it is set.
       Exit & Copy                 Clipboard only.
       Exit                        Keep the saved session so the next
                                   |:Review| resumes where you left off.

     The two copy options clear the saved session. With no comments, `q`
     exits immediately with no menu.
  5. Paste into your agent, or let tmux have done it for you.

|:Review| export and |:Review| send do the same export without closing the
UI. "Copy & Send" fails quietly when Neovim is not inside tmux, so you still
get the clipboard copy and no error popup.

The generated markdown groups comments by file, and each one carries its type
label, file, line, and a fenced code block of surrounding diff context: >

    # Code Review Comments

    ## src/api/client.ts

    ### [FIX] src/api/client.ts:42

    ```typescript
     const res = await fetch(url)
    +return res.json()
     }
    ```

    Handle a non-2xx response here.
<
When a commented line has no diff context available, the exporter falls back
to reading the file from disk and marks the block "(no changes)".

10. TROUBLESHOOTING                                   *review-troubleshooting*

Start with `:checkhealth review`, which verifies the Neovim version, git and
the repository, tmux and $TMUX, whether `setup()` has run, the log level, and
the log file path. "`setup()` has not been called" is reported as a warning,
not an error: the defaults are in effect either way.

:Review is not a command ~
    The plugin has not loaded. See |review-installation|. If you lazy-load,
    make sure the trigger fires before you type the command.

The toggle mapping does nothing ~
    `keymaps.toggle` is created by `setup()`. Under a lazy-loaded spec the
    plugin has not loaded yet when you press the key. Use your plugin
    manager's own key trigger instead.

"Not running inside tmux" ~
    |:Review| send checks $TMUX. Neovim must itself be running inside a tmux
    session; it cannot paste into a tmux server it is not attached to.

Sending succeeds but nothing appears in the agent ~
    The paste went somewhere else. With the default `tmux.target` of "!" it
    lands in the last active pane, which is not your agent if you moved
    through another pane on the way to Neovim. Set a fixed target instead.
    List the real ones with >

        tmux list-panes -a -F '#{session_name}:#{window_index}.#{pane_index}'
<
    and use a fully qualified target such as "session:window.pane", either
    in `tmux.target` or as the argument to |:Review| send.

No file icons ~
    nvim-web-devicons is not installed. Optional; everything else works.

The diff is not syntax highlighted ~
    No tree-sitter parser is installed for that language. Install it with
    `:TSInstall <lang>`.

Comments came back from a previous session ~
    `persistence.enabled` is on. Delete `.git/review-session.json` in the
    repository, or set `persistence = { enabled = false }`.

Checkout or branch creation refuses to run ~
    Both refuse on a dirty worktree. Commit or stash first.

Reading the log ~
    Run |:Review| log, or open the file directly: by default it is
    `review.nvim/review.log` under the system temp directory, typically
    `/tmp/review.nvim/review.log`. Set `log_file` to keep it elsewhere.

Filing a bug report ~
    Set `log_level = "DEBUG"` in `setup()`, reproduce the problem, then
    attach the contents of |:Review| log. DEBUG traces git operations, the
    layout lifecycle and the commit and amend flows.
